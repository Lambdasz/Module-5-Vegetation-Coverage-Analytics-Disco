# Vegetation Coverage Analytics (Module 5)

Plugin skeleton for the Aerial Analytics Platform. It follows the Module 2 plugin
contract (`plugins/template`, `plugins/mock`). Detection is simulated for now; the
real ExG/VARI/GLI pipeline replaces `simulate_detection()` in `main.py`.


## Module 5 Overview
Module Five analyzes the extent of vegetation cover based on vegetation data detected by Module Four. This module generates analytical data, ranging from the percentage of the area covered by vegetation to comparisons of vegetation cover across different plots. This data can subsequently be utilized by other relevant modules.
#### Purpose 
- Calculating the percentage of the area covered by vegetation
- Calculating the total area covered by vegetation
- Classifying areas into low, medium, or high vegetation cover categories
- Dividing the analysis area into smaller zones (a grid)
- Calculating vegetation cover for individual plots
- Comparing vegetation cover across selected plots
- Generating JSON artifacts/data containing vegetation coverage statistics and spatial results, which can subsequently be displayed on a map

### Module 5 Public Function & Contracts
## 1. `load_mask`

**Purpose:** Reads the vegetation mask image file generated by Module 4 and converts it into a 2D binary array that can be used  for processing by other functions in Module 5.

**Input:**
- `mask_path` (string) the file path to the mask, provided by Module 4.

**Output:**
- `binary_mask` (2D array, height × width, uint8)

**Note:**
- A prerequisite step that must be executed before other functions in Module 5 can run.
- Highly dependent on the file format produced by Module 4 please confirm the mask format and resolution with the team responsible for Module 4.

---

## 2. `calculate_vegetation_coverage`

**Purpose:** Calculates the percentage of vegetation cover and estimates the area covered by vegetation in square meters (m²).

**Input:**
- `binary_mask` (2D array)
- `gsd` (float, optional) obtained from Module 1 if unavailable, calculated automatically based on drone metadata (or similar sources).

**Output (dict):**
- `total_pixels` (int)
- `vegetation_pixels` (int)
- `coverage_percentage` (float)
- `vegetation_area_sqm` (float)
- `total_area_sqm` (float)

**Note:**
- Area calculations (`vegetation_area_sqm`, `total_area_sqm`) are only accurate if the GSD is available otherwise, the output will be limited to the percentage value.
- This output is used by Module 10 (Temporal Change) and Module 11 (Dashboard).

---

## 3. `classify_coverage`

**Purpose:** Classifies the level of vegetation cover (low/medium/high) based on the coverage percentage relative to predefined thresholds.

**Input:**
- `coverage_percentage` (float)
- `threshold` (dict): contains threshold values for `"low"`, `"medium"`, and `"high"` categories provided as user input via Module 2 (user-configurable, not hardcoded).

**Output:**
- `classification` (string: `"low"` / `"medium"` / `"high"`)

**Note:**
- The thresholds are user configurable through the Module 2 parameter system (via a `parameters.json` mechanism), which is then passed along using `execution_payload.json`. Regarding default values let’s discuss those later.
- The output is consumed by Module 11 (Dashboard).

---

## 4. `generate_coverage_zonation`

**Purpose:** Divides a vegetation mask into an N×N grid, calculates the coverage for each grid cell, and generates georeferenced vector data to be displayed as a map layer.

**Input:**
- `binary_mask` (2D array)
- `image_bounds` (list of 4 floats: `[min_lon, min_lat, max_lon, max_lat]`)  from Module 1
- `grid_size` (int, default: 4) provided as user input via Module 2 (user-configurable)
- `gsd` (float)  from Module 1
- `threshold` (dict)  from Module 2, used for classification per cell  <-- we still unsure, further discussion needed

**Output (dict):**
- A grid polygon layer with `[lon, lat]` coordinates, including statistical attributes for each cell sent to Module 3.

**Note:**
- Is `grid_size` a single integer (rather than a `"4x4"` format) implying that a default value of 4 results in a 4×4 grid? (To be clarified.)
- The result is consumed by Module 3 (Map Explorer) as an overlay layer.

---

## 5. `calculate_plot_coverage`

**Purpose:** Calculates and analyzes vegetation coverage specifically within the boundaries of a defined plot area.

**Input:**
- `binary_mask` (2D array)
- `threshold` (dict) from Module 2
- `polygon_coords` (list of `[lon, lat]`) from Module 9
- `image_bounds` (list of 4 floats `[min_lon, min_lat, max_lon, max_lat]`) from Module 1
- `plot_id` (string) from Module 9
- `gsd` (float) from Module 1

**Output (dict):**
- `plot_id` (string)
- `coverage_percentage` (float)
- `vegetation_area_sqm` (float)
- `classification` (string: `"low"` / `"medium"` / `"high"`)

**Note:**
- Requires the plot boundary geometry (polygon) from Module 9 the function cannot operate without it.
- The output is consumed by Module 9 and Module 11.

---

## 6. `compare_plots_coverage`

**Purpose:** Aggregates coverage results from multiple plots calculating the average, identifying the plots with the highest/lowest values, and ranking all plots.

**Input:**
- `plots_summary` (a collection of results from `calculate_plot_coverage`)

**Output (dict):**
- `average_coverage` (float)
- `highest_plot` (dict)
- `lowest_plot` (dict)
- `ranked_plots` (list of dicts)

**Note:**
- Relies on the results of `calculate_plot_coverage`, which must be computed beforehand for all plots being compared.
- The output is consumed by Module 9 and Module 11.

---

## 7. `generate_coverage_visualization`

**Purpose:** Generates a transparent PNG image (RGBA) representing a vegetation density heatmap (red,yellow,green), along with a statistical summary of the distribution, for display on maps and dashboards.

**Input:**
- `binary_mask` (2D array)
- `output_path` (string)  from Module 2
- `grid_size` (int, default: 4)  from Module 2
- `colormap` (dict, optional) from Module 2

**Output (dict):**
- `overlay_image_path` (string) sent to Module 3
- `distribution_stats` consumed by Module 11

**Note:**
- The overlay PNG file is rendered by Module 3 on top of the base map.
- The distribution statistics are used by Module 11 for dashboard charts.

## Files

| File                     | Purpose                                                                                                       |
| :----------------------- | :------------------------------------------------------------------------------------------------------------ |
| `manifest.json`          | Plugin identity, runtime, timeout                                                                             |
| `parameters.json`        | User-configurable parameters (`index_type`, `threshold`, `export_mask`)                                       |
| `inputs.json`            | Input requirements (single image, JPEG/PNG/TIFF, optional AOI)                                                |
| `outputs.json`           | Metrics (`vegetation_coverage_pct`, `total_pixels_analyzed`) and artifacts (`mask_image`, `geojson_boundary`) |
| `execution_payload.json` | Sample payload delivered by Module 2                                                                          |
| `execution_result.json`  | Sample result written by the plugin                                                                           |
| `main.py`                | Entrypoint (`--healthcheck`, `--input`/`--output`)                                                            |

## Public functions (Module 5 interface)

1. `python main.py --healthcheck` prints a healthy/unhealthy JSON and exits 0/1.
2. `python main.py --input <payload.json> --output <result.json>` runs the analysis,
   prints `PROGRESS: {"job_id", "percent", "stage"}` lines to stdout, and writes the
   result file. On error it writes `status: "failure"` and exits 1.
